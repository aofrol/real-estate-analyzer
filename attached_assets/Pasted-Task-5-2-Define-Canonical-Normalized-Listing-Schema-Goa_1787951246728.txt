Task #5.2 — Define Canonical Normalized Listing Schema

Goal:
Define the framework-independent canonical dictionary schema produced by
Normalizer implementations.

This task defines the DATA CONTRACT only.

Do NOT implement MockNormalizer yet.
Do NOT implement normalization algorithms yet.

==================================================
2. NORMALIZED LISTING TYPE
==================================================

Create a framework-independent TypedDict named:

NormalizedListing

Use Python standard library typing only.

Do NOT use:
- Pydantic;
- dataclasses;
- SQLAlchemy;
- ORM models.

NormalizedListing must represent canonical application-level listing data.

Use clear canonical field names and explicit units.


Required fields:

external_id: str

address: str

area_sqm: float

rooms: int | None

is_studio: bool

floor: int | None

total_floors: int | None

asking_price_kopecks: int

asking_price_per_sqm_kopecks: int


Optional / nullable canonical fields:

city: str | None

latitude: float | None

longitude: float | None

source_url: str | None

building_type: str | None

listed_at: datetime | None


Use datetime from Python standard library.


==================================================
3. IMPORTANT SEMANTICS
==================================================

Document these rules:

- money is represented in integer kopecks;
- area is represented in square metres;
- rooms represents room count;
- studios use:
    is_studio = True
  and:
    rooms = None
- floor and total_floors may be unknown;
- latitude and longitude may already be supplied by a source;
- Normalizer does NOT perform geocoding;
- source_url is an external listing URL if available;
- external_id is the listing identity assigned by the external source.

VERY IMPORTANT:

Do NOT include:

- source_id;
- building_id;
- property_id;
- listing_id;
- duplicate_of_id;
- database UUIDs of any kind.

Those values belong to persistence/entity matching layers, not normalization.
