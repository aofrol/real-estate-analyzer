Task #5.5 — Harden Ingestion Contracts

Goal:
Clean up the ingestion boundary before building entity matching.

Fix exactly two architectural issues:

1. source_id ownership must belong to application/persistence orchestration,
   not to the external raw payload;

2. RawListingRepository.save() must have one consistent return contract across
   the abstract interface and SQLAlchemy implementation.

Do not add new product functionality.


CURRENT FLOW

SourceAdapter
    ↓
Collector
    ↓
raw external dictionary
    ↓
IngestionService
    ↓
RawListingRepository
    ↓
raw_listings

==================================================
2. SOURCE_ID OWNERSHIP
==================================================

source_id is an internal database/application identifier.

It must NOT come from:

- SourceAdapter;
- Collector;
- raw external payload.

It must be supplied explicitly to IngestionService by application orchestration.


Update IngestionService so that source_id is injected explicitly.

Preferred design:

class IngestionService:

    def __init__(
        self,
        collector: Collector,
        repository: RawListingRepository,
        source_id: UUID,
    ) -> None:
        ...


Use UUID from Python standard library.


The service should store:

self._source_id


Do NOT require each raw payload to contain source_id.


==================================================
3. INGESTION MAPPING
==================================================

For every collected raw listing:

external_id must still come from the external payload.

raw_data must preserve the external payload.

Repository persistence should conceptually receive:

source_id=self._source_id
external_id=<external payload external_id>
raw_data=<external payload>


IMPORTANT:

Do NOT inject source_id into raw_data.

raw_data must remain source data, not database metadata.


==================================================
4. EXTERNAL_ID VALIDATION
==================================================

At the ingestion boundary:

external_id must exist in the collected raw payload and must be a non-empty
string.

If invalid, raise ValueError containing:

external_id

Keep validation narrow.

Do not duplicate normalization validation for:

- address;
- area;
- price;
- rooms;
- currency.

Those belong later in normalization.


==================================================
5. RAW LISTING REPOSITORY CONTRACT
==================================================

Inspect the current mismatch between:

RawListingRepository.save()

and:

SQLAlchemyRawListingRepository.save()


Choose one consistent contract.

Preferred contract:

save(
    *,
    source_id: UUID,
    external_id: str,
    raw_data: dict[str, Any],
) -> RawListing

However:

The abstract repository layer should preferably not depend on the concrete
SQLAlchemy ORM model if the current architecture already separates such
contracts.

Therefore inspect the existing repository architecture first.

Use the smallest change consistent with the current project style.

If RawListingRepository already imports/uses RawListing as its persistence
return type elsewhere, standardize both methods to return RawListing.

If keeping the repository abstraction framework-independent is clearly the
existing architectural intent, define a small appropriate return contract
instead.

DO NOT invent a large repository DTO architecture.

The key requirement is:

abstract signature == implementation signature

and:

abstract return contract == implementation return contract.


==================================================
