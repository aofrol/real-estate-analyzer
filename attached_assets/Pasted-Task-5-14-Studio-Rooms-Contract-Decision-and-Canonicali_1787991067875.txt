Task #5.14 — Studio Rooms Contract Decision and Canonicalization

Goal:
Resolve the current studio rooms contract mismatch before Property resolution
and persistence.

Current mismatch:

NormalizedListing.rooms:
    int | None

MockNormalizer studios:
    rooms=None
    is_studio=True

Property.rooms:
    SmallInteger
    NOT NULL

PropertyCandidate.rooms:
    int | None

ConservativePropertyMatcher currently compares rooms exactly.

This task must establish ONE canonical application-wide studio representation.


==================================================
1. TARGET CONTRACT
==================================================

Adopt this canonical MVP rule:

NON-STUDIO:
    is_studio=False
    rooms must be a positive integer >= 1

STUDIO:
    is_studio=True
    rooms must be exactly 0


Canonical studio representation:

rooms=0
is_studio=True


Do NOT use:

rooms=None
rooms=1

for studios after this task.


==================================================
2. WHY THIS CONTRACT
==================================================

The rationale is:

1. Property.rooms is already NOT NULL;
2. Property.rooms is SmallInteger;
3. rooms=0 clearly distinguishes studio from a one-room apartment;
4. is_studio remains the explicit semantic flag;
5. no database migration is required;
6. normalization, matching, candidate loading, and future persistence can all
   use the same representation;
7. avoiding representation conversion only at persistence prevents mismatch
   between normalized and persisted data.
