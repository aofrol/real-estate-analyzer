Task #5.1 — Create Normalizer Interface

Goal:
Introduce the normalization layer contract for the real-estate data pipeline.

Current architecture:

External Source
    ↓
SourceAdapter
    ↓
Collector
    ↓
IngestionService
    ↓
RawListingRepository
    ↓
raw_listings
    ↓
Normalizer
    ↓
Building / Property / Listing

This task must create ONLY the normalization interface.

Do not implement normalization logic yet.


CREATE ONLY:

backend/app/normalization/__init__.py
backend/app/normalization/base.py
backend/tests/test_normalizer_interface.py


==================================================
1. NORMALIZATION PACKAGE
==================================================

Create:

backend/app/normalization/__init__.py

Keep it minimal.

Do not add side effects.


==================================================
2. NORMALIZER ABSTRACT INTERFACE
==================================================

Create:

backend/app/normalization/base.py

Implement an abstract base class named:

Normalizer

Use Python standard library only:

- abc.ABC
- abc.abstractmethod
- typing.Any

The interface must expose exactly one normalization operation:

normalize(raw_listing: dict[str, Any]) -> dict[str, Any]

Requirements:

- Normalizer must inherit from ABC.
- normalize() must be decorated with @abstractmethod.
- normalize() must accept one raw listing dictionary.
- normalize() must return a normalized dictionary.
- The base class must contain no normalization implementation.
- Do not mutate the input in the abstract interface.
- Do not import SQLAlchemy.
- Do not import ORM models.
- Do not access the database.
- Do not perform persistence.
- Do not perform Building matching.
- Do not perform Property matching.
- Do not perform Listing matching.
- Do not perform deduplication.
- Do not perform geocoding.
- Do not perform source-specific parsing.

Add concise docstrings describing the architectural responsibility.

The Normalizer boundary is:

raw source-neutral dictionary
        ↓
Normalizer
        ↓
normalized source-neutral dictionary

The normalized result is NOT an ORM object.


==================================================
3. ARCHITECTURAL RESPONSIBILITY
==================================================

Document clearly in the class/module docstring:

Normalizer IS responsible for transforming source-specific/raw field representations into a canonical application-level data representation.

Examples of future normalization responsibilities may include:

- canonical field names;
- type conversion;
- area normalization;
- room/studio representation;
- price normalization;
- floor normalization;
- address field cleanup.

These are examples only.

DO NOT implement any of them in Task #5.1.


Normalizer IS NOT responsible for:

- database access;
- ORM object creation;
- persistence;
- source collection;
- API requests;
- geocoding;
- Building identity matching;
- Property identity matching;
- listing deduplication;
- comparable selection;
- valuation.
