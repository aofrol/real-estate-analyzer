Task #5.15 — Property Resolution Service

Goal:
Introduce a framework-independent PropertyResolutionService that translates
PropertyMatchResult into an explicit application decision:

- matched
- create_required
- ambiguous

The service must never turn ambiguity into creation.

This task is orchestration only.

Do NOT access the database.
Do NOT use SQLAlchemy.
Do NOT create or update Property rows.
Do NOT parse UUIDs.
Do NOT persist anything.

      ↓

2. CREATE PROPERTY RESOLUTION SERVICE
==================================================

Create:

backend/app/resolution/property.py


Implement:

@dataclass(frozen=True, slots=True)
class PropertyResolutionResult


Fields:

status: str
property_key: str | None
match_confidence: float
reason: str


Allowed status values:

"matched"
"create_required"
"ambiguous"


==================================================
3. PROPERTY RESOLUTION RESULT INVARIANTS
==================================================

Validate in __post_init__.


STATUS

status must be exactly one of:

- "matched"
- "create_required"
- "ambiguous"

Otherwise raise ValueError containing:

status


MATCH CONFIDENCE

match_confidence must:

- be numeric;
- not be bool;
- be finite;
- be between 0.0 and 1.0 inclusive.

Otherwise raise ValueError containing:

match_confidence


REASON

reason must be:

- str;
- non-empty after strip.

Otherwise raise ValueError containing:

reason


==================================================
4. MATCHED INVARIANT
==================================================

If:

status == "matched"

then:

property_key must be:
    - str;
    - non-empty after strip.

and:

match_confidence must be > 0.0


Invalid examples:

status="matched", property_key=None
status="matched", property_key=""
status="matched", match_confidence=0.0


Raise ValueError containing the relevant field name.


==================================================
5. UNRESOLVED INVARIANT
==================================================

If status is:

"create_required"
or
"ambiguous"

then:

property_key must be None

and:

match_confidence must equal 0.0


Invalid examples:

status="create_required", property_key="abc"
status="ambiguous", property_key="abc"
status="create_required", match_confidence=0.5
status="ambiguous", match_confidence=0.5


Raise ValueError containing the relevant field name.

6. CREATE PROPERTY RESOLUTION SERVICE
==================================================

Implement:

class PropertyResolutionService


Constructor:

def __init__(
    self,

) -> None:
    self._matcher = matcher


Method:

def resolve(
    self,
    *,
    listing: NormalizedListing,
    building_key: str,
) -> PropertyResolutionResult:
    ...


==================================================
7. MATCHER INVOCATION
==================================================

Call:

self._matcher.match(
    listing=listing,
    building_key=building_key,
)

exactly once.


Forward:

- the exact same listing object;
- the exact same building_key string.


Do NOT:

- copy listing;
- mutate listing;
- normalize building_key;
- parse UUIDs;
- perform DB lookups.


==================================================
8. MATCHED RESULT
==================================================

If:

match_result.matched is True

return:

PropertyResolutionResult(
    status="matched",
    property_key=match_result.candidate_key,
    match_confidence=match_result.confidence,
    reason=match_result.reason,
)


Do not alter:

candidate_key
confidence
reason


==================================================
9. CREATE REQUIRED REASONS
==================================================

The following unmatched matcher reasons mean a new Property may be needed:

"no_property_candidates"

"no_exact_property_signature"


Map both to:

PropertyResolutionResult(
    status="create_required",
    property_key=None,
    match_confidence=0.0,
    reason=match_result.reason,
)


IMPORTANT:

Do not create the Property here.

This service only returns the application decision.


==================================================
10. AMBIGUOUS REASON
==================================================

The following matcher reason must map to:

"ambiguous_property_candidates"


Return:

PropertyResolutionResult(
    status="ambiguous",
    property_key=None,
    match_confidence=0.0,
    reason=match_result.reason,
)


CRITICAL SAFETY RULE:

ambiguous_property_candidates

must NEVER become:

create_required


This prevents duplicate Property creation when multiple existing Properties
already share the same descriptive signature.


==================================================
11. UNKNOWN UNMATCHED REASON
==================================================

If:

match_result.matched is False

and:

match_result.reason

is not one of:

- no_property_candidates
- no_exact_property_signature
- ambiguous_property_candidates

raise:

ValueError


Error message must contain:

Unsupported matcher reason


Example:

raise ValueError(
    f"Unsupported matcher reason: {match_result.reason}"
)


Do not silently default to create_required.


==================================================
12. MATCHED RESULT SAFETY
==================================================

PropertyMatchResult already enforces:

matched=True
    → non-empty candidate_key
    → confidence valid


Do not duplicate matcher validation unnecessarily.

PropertyResolutionResult will independently validate its own invariants.


==================================================
13. BUILDING KEY RESPONSIBILITY
==================================================

PropertyResolutionService must NOT validate or parse building_key beyond simply
passing it to the matcher.

The matcher/provider layer already owns building_key validation where
appropriate.

This service remains orchestration-only.
