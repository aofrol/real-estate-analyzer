Task #5.4 — Introduce Normalization Service Boundary

Goal:
Create a small application-level service that converts a persisted raw listing
record into the framework-independent input expected by Normalizer.

This task defines the boundary between:

raw_listings persistence
        ↓
NormalizationService
        ↓
Normalizer
        ↓
NormalizedListing

The Normalizer itself must remain completely unaware of SQLAlchemy and ORM models.


==================================================

==================================================
2. ARCHITECTURAL RULE
==================================================

The normalization layer remains framework-independent.

Therefore:

Normalizer.normalize(...)

must continue receiving:

dict[str, Any]

and must NOT receive:

- SQLAlchemy ORM objects;
- Session;
- repositories;
- database UUIDs;
- RawListing model instances.

Do not modify the Normalizer interface.


==================================================
3. CREATE NORMALIZATION SERVICE
==================================================

Create:

backend/app/normalization/service.py

Implement:

class NormalizationService

Constructor:

def __init__(self, normalizer: Normalizer) -> None

Store the injected normalizer.

Expose one method:

normalize_raw_listing(...)

The method should accept only the minimum values needed from a persisted raw
listing record.

Preferred framework-independent signature:

def normalize_raw_listing(
    self,
    *,
    external_id: str,
    raw_data: dict[str, Any],
) -> NormalizedListing:

Do NOT accept a SQLAlchemy RawListing object.

Do NOT accept source_id.

Do NOT accept Session or repository objects.


==================================================
4. RAW PAYLOAD RECONSTRUCTION
==================================================

The persisted raw listing has:

- external_id stored as an application/database column;
- raw_data stored as the immutable/raw source payload.

The service must construct a NEW dictionary for the Normalizer.

Rules:

1. start from a shallow copy of raw_data;

2. ensure external_id passed to Normalizer comes from the persisted
   external_id argument;

3. do NOT mutate raw_data;

4. do NOT inject source_id;

5. do NOT inject any database UUID;

6. do NOT inject ORM metadata;

7. call:

   self._normalizer.normalize(normalizer_input)

8. return the resulting NormalizedListing.


==================================================
5. EXTERNAL_ID OWNERSHIP RULE
==================================================

This is important.

The database column external_id is authoritative at this boundary.

If raw_data also contains "external_id", do NOT trust it.

NormalizationService must overwrite it with the persisted external_id argument.

Example:

external_id argument:
"mock-001"

raw_data:
{
    "external_id": "wrong-value",
    ...
}

Normalizer must receive:

{
    "external_id": "mock-001",
    ...
}

This prevents divergence between persisted listing identity and duplicated
identity inside raw JSON.


==================================================
6. SOURCE_ID RULE
==================================================

Do NOT pass source_id into Normalizer.

source_id is an internal persistence/application identity and is not part of
the canonical normalized listing.

Do not modify NormalizedListing to include source_id.

Do not modify MockNormalizer to know about source_id.


==================================================
7. VALIDATION
==================================================

NormalizationService should perform only boundary-level validation.

At minimum:

- external_id must be a non-empty string;
- raw_data must be a dictionary.

Raise:

ValueError

with concise messages for invalid input.

Do not duplicate MockNormalizer's domain validation.

For example, address/area/price validation remains the Normalizer's
responsibility.
