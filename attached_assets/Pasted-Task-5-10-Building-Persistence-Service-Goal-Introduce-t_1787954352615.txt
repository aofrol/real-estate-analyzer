Task #5.10 — Building Persistence Service

Goal:
Introduce the first controlled persistence step that turns a
BuildingResolutionResult into an actual persisted Building reference.

This task must support:

1. reusing an already matched Building;
2. creating a new Building when resolution status is "create_required";
3. refusing to create anything when resolution status is "ambiguous".

Do NOT implement Property persistence yet.
Do NOT implement Listing persistence yet.
Do NOT modify matching logic.


CURRENT FLOW

NormalizedListing
        ↓
BuildingResolutionService
        ↓
BuildingResolutionResult
        ↓
BuildingPersistenceService
        ↓
existing Building OR newly created Building
        ↓
BuildingPersistenceResult

==================================================

Create:

backend/app/persistence/__init__.py

Define:

@dataclass(frozen=True, slots=True)
class BuildingPersistenceResult


Fields:

created: bool


Semantics:

building_key
    String representation of the persisted Building identity.

created
    False if an existing matched Building was reused.
    True if a new Building row was created.

==================================================
5. STATUS: MATCHED
==================================================

If:

resolution.status == "matched"

the service must NOT create a new Building.

It must:

1. validate/parse resolution.building_key as the Building primary-key type
   expected by the model;

2. load the existing Building using the injected Session;

3. if found:
   return:

   BuildingPersistenceResult(
       building_key=str(building.id),
       created=False,
   )

4. if not found:
   raise ValueError containing:

   building_key


This protects against stale or invalid matcher candidate keys.


==================================================
6. LOADING EXISTING BUILDING
==================================================

Use the simplest SQLAlchemy 2.x lookup appropriate for a primary key.

Preferred if consistent with project style:

self._session.get(Building, parsed_uuid)

Do NOT:

- update the existing Building;
- merge listing data into it;
- refresh building fields;
- perform candidate lookup again;
- call the matcher again.


==================================================
7. STATUS: CREATE_REQUIRED
==================================================

If:

resolution.status == "create_required"

create exactly one Building ORM object from the NormalizedListing.


Map fields:


address_raw
    listing["address"]


address_normalized
    canonicalize_address(listing["address"])


city
    listing["city"]


floors_total
    listing["total_floors"]


building_type
    listing["building_type"]


location
    See LOCATION RULE below.


Do not populate fields that cannot be safely derived:

district
street
house_number
postal_code
year_built

Leave them None/default.


==================================================
8. LOCATION RULE
==================================================

Inspect the actual Building.location configuration.

If:

listing["latitude"] is not None
AND
listing["longitude"] is not None

do NOT invent unsafe GeoAlchemy/PostGIS serialization.

Only populate location if the project already contains a simple, established,
tested pattern for assigning a geography POINT to Building.location.

If no such established pattern exists:

set:

location=None

for Task #5.10.


Document this decision.

Do NOT:

- create WKTElement unless already an established project convention;
- manually serialize WKB;
- issue PostGIS SQL;
- add new dependencies.

Geographic persistence can be added in a later dedicated task.


==================================================
9. CREATE + FLUSH
==================================================

For create_required:

1. instantiate Building;
2. session.add(building);
3. session.flush();

Do NOT commit.

Transaction ownership remains outside this service.

After flush, Building.id must be available.

Return:

BuildingPersistenceResult(
    building_key=str(building.id),
    created=True,
)


==================================================
10. STATUS: AMBIGUOUS
==================================================

If:

resolution.status == "ambiguous"

the service must:

- NOT query for creation;
- NOT create Building;
- NOT add;
- NOT flush;
- NOT commit.

Raise ValueError containing:

ambiguous


This is a hard safety boundary against duplicate building creation.


==================================================
11. UNKNOWN STATUS
==================================================

BuildingResolutionResult already validates allowed statuses.

Do not duplicate large status validation logic.

A defensive final branch may raise ValueError if somehow reached.


==================================================
12. ADDRESS VALIDATION
==================================================

For create_required:

use:

canonicalize_address(listing["address"])

This already validates empty/non-string addresses.

Do not duplicate address parsing logic.


==================================================
13. BUILDING KEY PARSING
==================================================

Building currently uses UUID primary keys.

If inspection confirms that:

for matched status parse:

resolution.building_key

using Python UUID.

If parsing fails:

raise ValueError containing:

building_key


Do NOT silently pass arbitrary strings into Session.get.


==================================================
14. DO NOT CREATE A BUILDING REPOSITORY YET
==================================================

For this small MVP step, use the injected SQLAlchemy Session directly inside
BuildingPersistenceService.

Do NOT introduce:

BuildingRepository
SQLAlchemyBuildingRepository

unless an existing abstraction already clearly requires it.

We do not want unnecessary abstraction layers before the persistence behavior
is proven.


==================================================
15. IMPORTANT TRANSACTION RULE
==================================================

BuildingPersistenceService:

MAY:
- session.get(...)
- session.add(...)
- session.flush()

MUST NOT:
- session.commit()
- session.rollback()
- create sessions
- close sessions

Transaction ownership is external.
