Task #5.18 — Listing Persistence Service

Goal:
Implement the ORM-aware persistence boundary for Listing identity and mutable
marketplace state according to:

docs/listing-identity-contract-v0.1.md

The service must enforce:

(source_id, external_id) = hard Listing identity

and must:

1. create a Listing when this source identity does not exist;
2. reuse the existing Listing when it already exists;
3. never create a second Listing for the same source_id + external_id;
4. fail closed if an existing Listing is associated with another Property;
5. preserve duplicate_of_id;
6. never perform cross-source deduplication;
7. never create ListingPriceHistory;
8. never own the transaction.

This task implements Listing persistence only.

Do NOT implement price-history behavior yet.
Do NOT implement deduplication yet.
Do NOT change schema or migrations.

==================================================
2. CONTRACT SOURCE OF TRUTH
==================================================

Use:

docs/listing-identity-contract-v0.1.md

as the identity contract.

Hard identity:

(source_id, external_id)


Meaning:

same source_id + same external_id
    → same Listing row

Different external_id
    → different Listing identity

Different source_id
    → different Listing identity


Do NOT use:

property_id
source_url
price
address

as Listing identity.

backend/app/persistence/listing.py

==================================================
4. INPUT RESPONSIBILITIES
==================================================

Inputs:

source_key:
    Source UUID represented as application string

property_key:
    Property UUID represented as application string

listing:
    canonical NormalizedListing


The service may:

- validate UUID strings;
- load Source;
- load Property;
- query Listing by source_id + external_id;
- create Listing;
- update allowed mutable Listing fields;
- add;
- flush.


It must NOT:

- normalize raw source data;
- perform building/property matching;
- perform property resolution;
- perform cross-source deduplication;
- modify duplicate_of_id;
- create ListingPriceHistory;
- persist RawListing;
- commit;
- rollback;
- close session.

==================================================

non-empty string.

external_id


Do not mutate or normalize the value.

Do not assume numeric.

Do not strip/change the persisted value after validation.

Do NOT add another uniqueness mechanism.

==================================================
22. URL UPDATE
==================================================

If Listing has a URL field:

source URL is mutable metadata.


Set it from:

listing["source_url"]


for both create and reuse.


It is NOT identity.


If canonical URL is None and existing URL is non-null:

inspect contract/model intent.

Preferred MVP behavior:

do not destroy a known existing URL merely because a later source observation
omits it.


Therefore:

on reuse:
    update URL only when listing["source_url"] is not None.

on create:
    persist canonical value, including None if nullable.


Document exact behavior.

==================================================

- create using existing model/default status;
- preserve existing status on reuse.


Do not derive "active" merely from observation unless existing architecture
already explicitly establishes this behavior.


Report this clearly.


==================================================
26. LISTED_AT UPDATE ON REUSE
==================================================

listed_at represents original source publication time.


Preferred behavior:

- create: map canonical listed_at;
- reuse:
    - if existing.listed_at is None and canonical listed_at is not None:
          populate it;
    - otherwise preserve existing listed_at.


Do NOT overwrite an existing publication timestamp on each reobservation.


If project docs specify a different rule, follow the docs and report it.
