Task #5.9 — Introduce Building Resolution Service

Goal:
Introduce an application-level service that decides whether a normalized
listing resolves to an existing building or requires creation of a new
building.

This task adds orchestration only.

Do NOT create Building ORM records yet.
Do NOT write to PostgreSQL.
Do NOT add a BuildingRepository yet.


CURRENT FLOW

NormalizedListing
        ↓
BuildingResolutionService
        ↓
BuildingMatcher
        ↓
BuildingMatchResult
        ↓
BuildingResolutionResult

Possible outcomes:

1. existing building resolved;
2. new building creation required;
3. ambiguous match requiring explicit handling.

==================================================
3. RESULT SEMANTICS
==================================================

STATUS: matched

Meaning:
The listing has been confidently resolved to an existing building.

Requirements:

building_key:
    non-empty string

match_confidence:
    > 0.0 and <= 1.0


STATUS: create_required

Meaning:
No existing candidate matched and future persistence should create a new
Building.

Requirements:

building_key:
    None

match_confidence:
    0.0


STATUS: ambiguous

Meaning:
Candidates existed, but the matcher could not safely identify one building.

Requirements:

building_key:
    None

match_confidence:
    0.0


==================================================
4. RESULT INVARIANTS
==================================================

Validate in __post_init__.

Required rules:

1. status must be exactly one of:

   matched
   create_required
   ambiguous

2. match_confidence must be numeric, finite, and between 0.0 and 1.0 inclusive;

3. matched requires non-empty building_key;

4. matched requires match_confidence > 0.0;

5. create_required requires building_key is None;

6. create_required requires match_confidence == 0.0;

7. ambiguous requires building_key is None;

8. ambiguous requires match_confidence == 0.0;

9. reason must be a non-empty string.

Raise ValueError with concise messages containing the relevant field name.

Do not add other business logic to the dataclass.

6. MAP MATCH RESULTS TO RESOLUTION RESULTS
==================================================

BuildingResolutionResult(

Do not alter the matcher reason.


==================================================
7. CREATION-REQUIRED REASONS
==================================================

The following matcher reasons mean that there is no safe existing building and
a new building may need to be created:

"no_candidates"
"no_exact_address_match"


For either reason, if matched=False, return:

BuildingResolutionResult(
    status="create_required",
    building_key=None,
    match_confidence=0.0,
    reason=<same matcher reason>,
)


Important:

This task does NOT actually create the Building.


==================================================
8. AMBIGUOUS REASON
==================================================

The matcher reason:

"ambiguous_exact_address"

must map to:

BuildingResolutionResult(
    status="ambiguous",
    building_key=None,
    match_confidence=0.0,
    reason="ambiguous_exact_address",
)


IMPORTANT:

An ambiguous result must NOT be converted into create_required.

Otherwise the system could create a duplicate Building when an existing
building is already present but cannot be uniquely resolved.


==================================================
9. UNKNOWN MATCHER FAILURE REASON
==================================================

Do not silently treat unknown unmatched matcher reasons as create_required.

If:

match_result.matched is False

and reason is not one of:

"no_candidates"
"no_exact_address_match"
"ambiguous_exact_address"

raise ValueError containing:

reason


This protects orchestration from silently misinterpreting future matcher
behaviour.

==================================================
12. WHY create_required IS NOT "created"
==================================================

Document this distinction clearly.

create_required means:

"No existing building was safely resolved, so a later persistence service may
create one."

It does NOT mean:

"A Building row has already been created."

Do not use status:

"created"

in Task #5.9.
